# СМЕНА

Мобильный штаб съёмочной площадки: вызывной, план дня, табель, контакты,
чаты, доска дня, сценарий, объекты, календарь КПП — в одном приложении с
общими данными на сервере и офлайн-кэшем на устройстве.

## Стек

- React 19 + TypeScript + Vite
- Tailwind CSS 4
- Supabase: PostgreSQL + Auth + Realtime (Row Level Security на каждой таблице)
- IndexedDB (через `idb`) — локальный кэш и очередь офлайн-операций
- Service Worker / PWA (`vite-plugin-pwa`)
- `pdfmake` — настоящий PDF с кириллицей (вызывной)
- `mammoth` — разбор DOCX при импорте сценария
- Vitest — тесты бизнес-логики

## Запуск

```bash
npm install
cp .env.example .env.local   # заполнить VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY
npm run dev
```

Значения для `.env.local` берутся в Supabase Dashboard → Project Settings →
API (URL и `publishable`/`anon` ключ). Секретный `service_role` ключ здесь
не нужен и никогда не должен попадать в клиентский код.

## Сборка и проверки

```bash
npm run build     # tsc -b && vite build
npm run lint       # oxlint
npx vitest run     # 25 тестов бизнес-логики
```

## База данных

Схема и миграции — в `supabase/migrations/`:

1. `0001_schema.sql` — таблицы: `projects`, `project_members`, `invites`,
   `join_attempts`, `contacts`, `locations`, `shifts`, `shift_status_log`,
   `member_shift_status`, `scenes`, `assignments`, `time_edit_log`,
   `board_events`, `channels`, `messages`, `kpp_days`. Каждая сущность —
   отдельная таблица (не один растущий JSON проекта).
2. `0002_rls_and_functions.sql` — RLS-политики на каждой таблице и все
   изменяющие операции через `SECURITY DEFINER` RPC-функции
   (`create_project`, `redeem_invite`, `set_shift_status`,
   `set_assignment_time` и т.д.), которые сами проверяют роль пользователя
   в проекте. Права проверяются на сервере — скрытие кнопок в интерфейсе не
   является единственной защитой.
3. `0003_harden_functions.sql` — фиксация `search_path` у функций и отзыв
   лишнего доступа `anon`/`PUBLIC` к служебным и RPC-функциям.

Применить к своему проекту Supabase:

```bash
supabase link --project-ref <ref>
supabase db push
```

(или выполнить файлы по порядку через SQL Editor в Dashboard).

## Архитектура офлайн-режима

- `src/lib/offline/db.ts` — единая IndexedDB (`idb`): кэш прочитанных
  сущностей + очередь исходящих операций (`outbox`) + мелкие ключи (черновики
  чатов, кэш последнего прочитанного).
- `src/lib/offline/cache.ts` — `fetchThroughCache`: при успешном запросе
  кладёт свежие данные в кэш, при сбое сети — отдаёт последнее сохранённое.
- `src/lib/offline/outbox.ts` + `src/lib/offline/syncHandlers.ts` — очередь
  отправки сообщений чата, записей доски дня и своего статуса. Каждая
  операция несёт `client_op_id`, уникальный на сервере (`unique` индекс в
  БД), поэтому повторная отправка после сбоя не создаёт дубликатов.
  `OutboxSync` (смонтирован в `AuthGate`) пытается отправить очередь при
  старте и по событию `online`.
- Роли ролей и разрешения дублируются на сервере (RLS + RPC), клиент только
  прячет недоступные кнопки для удобства.

## Роли

- **Владелец** — управляет проектом, участниками и приглашениями.
- **Координатор** — редактирует расписание, вызывной, сцены, табель, доску
  дня (записи `change`/`lunch`).
- **Участник** — читает данные, пишет в чаты и доску (заметки), меняет
  только свой личный статус («Мой статус» и время своего прибытия — это
  разные вещи: контакт в списке группы и учётная запись пользователя не
  одна и та же сущность, они лишь могут быть связаны через
  `contacts.linked_user_id`).

## Что реализовано

- Регистрация/вход через Supabase Auth (email+пароль); пустой старт —
  создать проект или присоединиться по коду.
- Множественное членство: один пользователь — несколько проектов,
  переключение между ними, архивирование.
- Приглашения с TTL, лимитом использований, отзывом; защита от перебора
  кодов — серверный rate-limit в RPC `redeem_invite` (не более 8 неудачных
  попыток за 10 минут на пользователя) плюс код из непредсказуемого
  7-символьного алфавита без похожих символов.
- Экран «Сегодня»: статус смены (подготовка/мотор/обед/стоп) с автором и
  временем, «Мой статус», сцены дня с сортировкой относительно начала смены
  (включая переход через полночь), счётчик на площадке, снято/план.
- Вызывной: собирается из текущих данных смены, короткая/полная версия,
  печать, настоящий PDF (кириллица, вызывной с несколькими страницами при
  полной версии — `Roboto` действительно содержит кириллические глифы),
  копирование текстовой версии, экспорт CSV плана дня.
- Площадка: группа/актёры/транспорт, отметки «приехал/стоп/уехал»,
  исправление времени с историей правок, расчёт отработанного времени и
  переработки по чётким и настраиваемым правилам (`src/lib/time.ts`,
  покрыт тестами), поиск и экспорт табеля в CSV.
- История смен: каждая смена — независимая запись, отметки времени не
  переносятся между сменами, контакты переиспользуются; просмотр истории
  на устройстве не переключает «текущую» смену у остальных.
- Календарь КПП: сетка месяца и список, типы дней, сегодня/завтра, карточка
  дня со ссылками на вызывной/табель, экспорт CSV.
- Сценарий: импорт TXT/Fountain/DOCX с разбором ИНТ./НАТ./INT./EXT.,
  предпросмотром (сколько сцен, дубликаты, нераспознанные заголовки) и
  выбором «создать/обновить» по стабильному ключу серия+номер сцены —
  повторный импорт не плодит дубликаты. Поиск по номеру/серии/локации/
  персонажу/тексту, отметка «снято», переход в обсуждение сцены, удаление.
- Объекты: группировка по локациям со стабильным ID, адрес/проезд/парковка,
  карта, поиск, экспорт CSV.
- Чаты: общий/цеховые/посценные каналы, реалтайм через Supabase Realtime,
  состояния отправки (сохранено локально/ожидает/на сервере/ошибка —
  без фальшивых «прочитано»), ответы с цитатой и переходом к оригиналу,
  поиск, черновики per-проект/канал в IndexedDB (переживают перезапуск),
  Enter — новая строка, Ctrl/Cmd+Enter — отправка, явная кнопка отправки.
- Доска дня: заметка/изменение/обед/погода с автором и временем.
- Офлайн-очередь для сообщений и записей доски с идемпотентной отправкой по
  `client_op_id`.
- CSV защищён от формул (экранирование `=`/`+`/`-`/`@`), от XSS — весь текст
  рендерится через React (без `dangerouslySetInnerHTML`), импорт скрипта
  ограничен по размеру файла (15 МБ) и типу.

## Честные ограничения

- **Реалтайм чатов и офлайн-очередь проверены только для одного клиента**
  в рамках этой сессии (два одновременных пользователя, два реальных
  телефона, гонка сообщений — не проверялись вживую; это требует второго
  устройства/сеанса). Прохождение unit-тестов логики — не то же самое, что
  проверка на реальных телефонах между реальными пользователями.
- Сеть в этой изолированной среде разработки блокирует прямой выход
  браузера к `*.supabase.co` (организационная политика egress-прокси), из-за
  чего сквозной прогон «регистрация → создание проекта → работа с данными»
  в реальном браузере в этой сессии не был доведён до конца — я убедился,
  что экран входа рендерится без ошибок и что сетевые сбои корректно
  показываются пользователю (проверено на форме регистрации), но полный UI-
  прогон стоит повторить в обычной сети. Схема, RLS и RPC-функции при этом
  проверены и применены напрямую через management-доступ к Supabase.
- Разрешение конфликтов при одновременном редактировании реализовано на
  уровне отдельных полей (каждое изменение времени/статуса — отдельная
  атомарная операция с историей в `time_edit_log`/`shift_status_log`, так
  что конфликты на уровне всей записи невозможны), но нет отдельного
  интерактивного UI «слияния» для случая, когда два человека одновременно
  меняют одно и то же поле оффлайн — выигрывает последняя синхронизированная
  запись, история сохраняется и видна, но явного предупреждающего диалога
  нет.
- Погода на доске дня — только вручную вписанная заметка; интеграция с
  реальным источником погоды не подключена (сознательно, чтобы не
  показывать выдуманные данные).
- Импорт сценария — эвристический разбор текста (заголовки, день/ночь,
  реплики персонажей); для нестандартно оформленных сценариев возможны
  ложные срабатывания предупреждений — это ожидаемо и поэтому импорт всегда
  проходит через экран предпросмотра перед сохранением.
- Резервное копирование/восстановление на уровне всего проекта (раздел 15)
  не реализовано отдельным экраном — данные защищены штатными бэкапами
  Supabase (Point-in-Time Recovery на платных планах) и разделением на
  таблицы с историей правок; полноценный экспорт/импорт всего проекта одним
  файлом можно добавить отдельно.
- Публичная ссылка на развёрнутое приложение не создавалась — в этой сессии
  нет подключённого хостинга; `npm run build` собирает готовый `dist/`,
  который можно опубликовать на любом статическом хостинге (Vercel,
  Netlify, Cloudflare Pages и т.п.), прокинув те же переменные окружения.
- PWA-иконки и офлайн-манифест подключены, но реальная установка на экран
  телефона и поведение Service Worker при обновлении версии проверялись
  только по конфигурации (`vite-plugin-pwa`, `registerType: 'prompt'`), не
  на физическом устройстве.

## Структура проекта

```
src/
  api/          — типизированные обёртки над Supabase (запросы и RPC)
  lib/           — чистая бизнес-логика (время/переработка, CSV, PDF,
                   разбор сценария, офлайн-кэш и очередь) — покрыта тестами
  state/         — auth и текущий проект/смена (zustand)
  context/       — ProjectContext (проект, участники, роль, текущая/
                   просматриваемая смена)
  layout/        — навигация, гейты, синхронизация очереди
  pages/         — экраны приложения
supabase/migrations/ — схема БД, RLS, RPC-функции
```
